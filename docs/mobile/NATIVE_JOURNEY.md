# Native first journey

`NativeJourney` renders the existing private session, navigation and bounded
reading runtime. The runtime owner selects the reviewed development environment,
transport and credential vault. The screen receives verified snapshots and
commands only. Importing the components activates no native module or network.

## Application owner and activation

The application entry now selects one owner through the pure configuration shared
with Expo's build configuration. An absent `EXPO_PUBLIC_APPLICATION_MODE` or the
literal `fixture` selects the labeled memory-only preview. The literal `native`
requires a fixed source-controlled accepted environment and HTTPS origin.
The bundled accepted configuration is currently `null`, so native selection shows
an unavailable screen. Empty, misspelled or unknown modes also stay unavailable.
An environment variable cannot supply an endpoint or approve a backend.

For an accepted configuration, the effect-owned application composes the existing
native JSON wire, secure credential vault and canonical runtime, then renders the
existing password journey. Configuration is copied and frozen before factories
run. Construction errors expose only an unavailable state, with no automatic
fixture, fetch or HTTP fallback. Each effect setup creates a fresh runtime;
cleanup disposes that runtime and cancels its work. Importing the composition
helper performs no native activation, storage read or network request. Creation
starts concealed, and the existing visibility observer controls foreground work.
The existing Android keyboard-first Back behavior applies to both owners.

Native mode has no fictional link parser, preview tools or diagnostic controls.
Real app/universal links and OS association remain separate acceptance work.
Only fixture configuration includes the local fixture network plugin. Removing
that plugin from configuration does not prove old generated manifests lost their
exceptions; native acceptance requires fresh generation or manifest inspection.
Native environment and build variant must match. Updates remain disabled.

Metro's cache identity includes both the requested mode and resolved selection.
The installed Expo native CI exporter ignores automatic cache resets, so a mode
switch otherwise reused an App transform with the previous inlined value.
Native and invalid modes keep separate identities even before backend acceptance;
later acceptance cannot turn a cached native literal into an invalid-mode login.
Absent and explicit fixture selections may reuse their equivalent transform.

The configuration and controlled-port lifecycle checks are source preparation.
They do not accept a staging endpoint, real native session, secure-store lifecycle,
device accessibility or either platform's complete journey. Activation still
requires the canonical backend's exact source/build, isolated fictional data,
disabled providers, native default-trust HTTPS and capability receipt.

The 8 October source checkpoint passes 223 mobile tests, including executable
entry-module tests that reproduced eager native binding before the repair.
Native adapter imports and the optional fixture storage probe are now deferred
until their guarded command. Controlled owner tests are distinct from React or
device lifecycle acceptance. Xcode 27 unsigned Simulator builds pass; sequential
native then fixture builds contain the correct, different inlined selections.
The native selection's unavailable screen was observed on iPhone SE with iOS
18.3.1. No real credential form or account data appeared. The corrected fixture
build then passed launch, demo sign-in, feed, post detail and sign-out on that
Simulator. Its explicitly invoked Keychain write/read/removal probe also passed.
The fixture sign-out response is fictional and does not prove server revocation.
The final fixture
Hermes bundle is 1,733,587 bytes, an increase of 75,171 bytes over the prior
fixture build; this is JavaScript size, not download size or a performance result.

Password entry uses the canonical native input contract. Values stay in the
short-lived form and are cleared before submission. A session-generation change
or concealment unmounts the form. Fixture mode presents a demo button and never
asks for real credentials. Native activation remains a separate acceptance gate.

The feed replaces each finite page. Post detail always uses a new authorized
read. Content notes conceal text, scripture and link metadata until reveal.
Plain reposts use the currently projected original and its content note. Quoted
originals remain independent previews requiring their own detail read. Missing
originals never fall back to obsolete wrapper content. Hidden counts remain
hidden, and church authors, audiences and closed discussions remain distinct.
Body links are inert text; this slice adds no media loads, writes or WebViews.

Sign-out conceals content immediately. Local removal and remote revocation have
separate, truthful status messages. Interrupted verification and read errors
show no previous private content and require explicit recovery. Only direct
member interaction sends an activity renewal; passive rendering and visible
authorization rechecks do not renew a session.

The visibility observer starts concealed, subscribes before reading state and
requires active plus window focus on Android. Inactive, background and blur
conceal immediately. Cleanup removes subscriptions and conceals without
disposing the process-owned runtime, so StrictMode effect remounts can reuse it.
Stale callbacks and activation failures cannot undo later lifecycle decisions.

React Native exposes Android focus events without an initial focus snapshot.
The local `GCNativeVisibility` Android module reads the current activity's window
focus on the main queue. Startup and each new active epoch query it after event
subscriptions attach. Only a literal `true` can open the visibility boundary;
missing modules, absent/destroyed activities and failed reads stay concealed.
Any newer focus, blur, background or teardown supersedes an outstanding reply.
Positive focus events prompt a new snapshot instead of opening content directly.
Duplicate active events cannot erase a known blur. This adds no polling, event
owner, permissions, storage or network work. iOS never queries this module.

The Android binary must be rebuilt to include the module. Autolink discovery,
source and race tests do not prove Kotlin compilation or device behavior. Verify
cold start after the last focus event, resume, notification shade, permission
dialogs and activity recreation on the actual build. Older binaries without the
snapshot module remain concealed and need a rebuild.
JavaScript lifecycle handling is not proof of an OS app-switcher privacy cover.
Native transport and storage, iOS/Android
builds, device lifecycle/network behavior, keyboard and assistive-technology
checks remain separate from source, type and unit-test evidence.
