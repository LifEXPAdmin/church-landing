# Current private Need contributions and post links

## Prepared scope, 8 October 2026 (America/Chicago)

This batch moves the remaining inline contribution cards and eligible church
post choices behind their current account-bound readers. Initial Need page
output carries only each reader's routing context. Private contribution notes,
quotes, dispute details, post excerpts and post pagination are withheld from
that initial output. Existing server authorization still runs; this does not
change who can read or manage a Need.

Inline contributions reuse the current contribution owner with an explicit
Need scope. Bounded replies must match the original account and Need. Each card
keeps its own unsent fields and original request. A confirmed receipt permits
only the expected next revision; unexplained sibling, ordering or cursor
changes keep the retained page concealed. Current progress and incoming
contribution owners remain in place.

The post reader owns one bounded page and its original Need revision. Link or
unlink confirmation must match the original Need, post, expected revisions and
requested link state. Unrelated post changes and changed pagination cannot be
accepted as that request's result. Temporary access uncertainty retains the
original request for deliberate recovery. Confirmed account replacement or
sign-out clears the prior private state for that visit.

Both readers check current focus, visibility and connectivity before admitting
a read and before presenting its response. The existing account guard, nested
recovery registration, roles, form contexts and loan/progress data are retained.
This adds no schema, dependency or background service. Reads stay bounded to
20 rows, with deliberate continuation and the existing foreground refresh cadence.
No performance improvement is claimed without measurement.

## Verification and remaining limits

Baseline modeled checks reproduced private inline data and post controls in
the current server page's initial output. Actual component bodies also reproduced
unfocused admission and delayed-response failures. These deterministic checks
use controlled dependencies and events; they do not establish browser focus,
built HTML/RSC, database, HTTPS, provider or production acceptance.

The combined source passes 693 source checks, lint and authored-copy validation.
Review also reproduced an already-presented post panel remaining visible after
an unfocused timer callback. The corrected callback conceals the retained panel
and requires a fresh pinned read after focus returns. The local dependency cache
lacks its generated Prisma client, so full type acceptance is deferred to the
isolated workflow that generates the client from this unchanged schema.

Fresh combined source checks, isolated built application journeys, enforced
HTTPS authorization, controlled React scenarios and exact release acceptance
are required before publication. Version 2026.10.08.16 remains the verified live
baseline while this candidate is prepared.

The whole Need page is not claimed to contain routing context only, and
concealment is not memory erasure. Later staged offer creation, accepted new
contribution insertion, other form rearming, rapid repeated Back, physical
devices, real provider delivery and production capacity remain separate.
