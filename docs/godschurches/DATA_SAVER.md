# Data saver on active media surfaces

## Current integration, 8 October 2026

The preserved small-preview feature is integrated with the current privacy
owners. Two controlled actual-component failures reproduced photo reloading and
late reply presentation while the document was visible but unfocused. Gallery
reads now require current focus, visibility and connectivity both before dispatch
and at settlement. Focused recovery still rechecks access and returns to the
small preview. No original-image or larger-image permission is carried forward.

The added foreground runner is scripts/qa-photo-foreground-client.mjs, invoked
with a new output directory. It tests eight actual React DOM scenarios with
modeled foreground and held fictional transport, with all network requests
blocked. The Node lifecycle suite executes the real component body separately.
These controlled checks do not establish native focus events, physical devices,
canonical service access or a full application run. Fresh combined hosted and
live acceptance remains pending.

## Preserved feature and original local evidence

The existing browser-local Reduce photo data setting now also controls the shared
photo viewer. Opening a photo starts with its thumbnail. Load larger photo shows
the approximate transfer size and requests the large variant only when selected.
Changing photos or rechecking current access returns to the small preview. Zoom
does not silently select a larger download. Normal viewing is unchanged when
Data saver is off. No original download, new setting owner or schema is added.

The shared viewer is used by post, listing, profile, album and support photo
surfaces. Their existing current-access reads and image endpoints remain the
permission owners. Post and listing galleries already use reduced-data preview
controls, and profile/album grids use thumbnail variants. Existing media-library
playback uses explicit external links; no native audio/video player or iframe is
activated by this work. Future player preferences need their own capability work.

Settings help now explains the explicit larger-image choice. The browser check
mounts the actual viewer and ReadingProvider, records image requests, verifies
keyboard activation, moving/zooming, access refresh, changed account, normal
mode and narrow-screen enlarged text. It uses fictional identity/gallery/image
responses and is not a full database or hosted acceptance test.

The preserved prior viewer fails the small-preview assertion. The changed viewer
passes seven browser groups, with zero original-image requests and browser
errors. There is no production deployment or live acceptance in this receipt.

```sh
DATA_SAVER_QA_DIR=/absolute/new-artifact-folder DATA_SAVER_QA_CSS=/absolute/build/.next/static/css node scripts/qa-data-saver-browser.mjs
```

For a baseline comparison only, `DATA_SAVER_BASELINE_SOURCE` can point to a
preserved prior viewer source file. The fixture loader substitutes that component
without editing the application. Failed baseline runs are retained separately.
