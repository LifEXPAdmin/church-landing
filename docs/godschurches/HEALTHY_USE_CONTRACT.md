# Adult reminders and enforced-limit boundaries

## Scope and source reconciliation

September 18, 2026 candidate on integrated baseline `9e66724`. This document specifies optional adult Word and Kingdom-service reminders, user overrides, inactivity, time zones and truthful enforcement labels. It does not implement a timer, preference store, child policy or notification channel.

The first adult runtime is an optional reminder for the current browser session. A saved account preference may load on another session; this does not make elapsed time or enforcement cross-device. Neither prompt measures Bible reading, faith, service completed, attention or compliance. Declining or disabling either prompt has no effect on account access, content visibility, privileges or spiritual standing.

Current owners to preserve:

| ------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `reading-preferences.ts` and its component                          | Presentation-only browser cookie, including reduced motion/data                                           | Do not put account identity, timer history or authority in this cookie or reset other preference families with it.                                           |
| `platform-measurement.ts` and `measurement-foreground.tsx`          | Separately disclosed optional measurement, limited trusted navigation signals and server collection rules | Not a continuous-use clock or a source of reading/serving time. Do not create a competing delivery schedule or reclassify security/recovery mail as optional.                    |

The persistence, settings integration, timer, reminder interface, playback integration, private history and family policy tasks retain their separate scope. Do not enable a working-looking control before its owning adapter exists.

## Defaults and adult choices

Both reminders are off by default, independently selectable and independently reversible. Enabling one must disclose the foreground-session estimate before the first timer starts. Do not infer consent from registration, account role, platform measurement, reminder dismissal or existing notification permissions.

| Choice                 | Suggested interval after opt-in | Meaning                                                                                                                               |
| ---------------------- | ------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| Word reminder          | 30 active minutes               | Optional invitation to pause and spend time in the Word; not proof of Bible reading and not a requirement to visit a particular page. |
| Kingdom-service prompt | 60 active minutes               | Optional invitation to take time away or serve someone; not a claim that an action or ministry commitment has been completed.         |

Each enabled interval may be changed to a whole number from 5 to 240 active minutes. Reject out-of-range, fractional or malformed values without replacing the last saved setting. Interval changes apply from the successful save forward, setting the next milestone to current measured active time plus the new interval. They never manufacture historical elapsed time or immediately replay missed prompts.

Each shown prompt offers Continue, Snooze, Take a break and a clear settings/disable action. Continue schedules that prompt's next milestone one selected interval after the current active total. Snooze offers 5, 15 or 30 additional active minutes, clearly labeled as active minutes in this browser session. Repeated clicks/retries do not create multiple pending prompts. Take a break pauses supported local playback/queued continuation and the reminder session; the browser cannot promise to close a tab or stop media already opened at an external provider. Resume starts a new reminder session, without changing saved opt-in choices.

Turning a reminder off dismisses its pending prompt and clears its milestone/snooze state immediately for the current runtime. Saving the off choice through the canonical owner makes it apply in later sessions. If that save fails, the interface must say that the last saved account choice still applies elsewhere and on reload; it may still let the adult dismiss this session's prompt. Disabling reminders never erases separately chosen history or changes analytics, notifications, autoplay or family policy implicitly.

## Active time and session scope

The timer task must use this explicit first-version scope: the signed-in eligible adult's current foreground, focused browser session. It is an estimate, not system-wide device screen time. It does not count other applications, another device, background audio, hidden tabs, suspended browser time or a provider's external window. Reading without interaction may be undercounted; disclose that limit without asking the user to prove attentiveness.

Count an interval only while the document is visible and focused and there has been a trusted pointer, keyboard, touch, scroll or playback-control interaction within the preceding five minutes. A passive page load, synthetic event, animation, timer, network request or server heartbeat is not an interaction. Observe event presence/time only, not key values, pointer coordinates, text, content identity or the user's reading topic. Accessibility interactions must work without requiring a pointer or a particular gesture.

Use monotonic elapsed time within one document; check visible/focus/idle eligibility at both boundaries. Sample no more often than needed for a bounded 15-second interval. Do not add a delayed interval greater than 30 seconds after suspension or an unknown visibility gap; restart the baseline and disclose possible undercounting. A manual wall-clock change or daylight-saving transition must not subtract time, invent time or fire many reminders. No background polling or server writes are required for this local elapsed counter.

Hidden, unfocused or idle state pauses counting immediately. After thirty continuous minutes without eligible foreground activity, discard the old reminder session and begin a new one on the next trusted interaction. This reset is unrelated to the similarly named analytics session gap. Normal client navigation preserves the same session counter; signing out, changing accounts, closing the session or explicit Take a break clears it. A full reload may reset the first-version local counter and must be described as such. Do not invent elapsed time from a wall-clock timestamp stored before reload.

Only one tab in a browser may present a reminder for the same account at once. Coordinate presentation through an account-scoped, short-lived tab owner where supported; losing focus/visibility releases presentation eligibility. Do not sum independently counted overlapping tabs. If reliable tab coordination is unavailable, state that timing is tab-local and allow only the focused tab to prompt. Private/incognito profiles and other devices remain separate; no cross-device claim follows from loading the same preferences.

Keep at most one visible reminder. If both thresholds are reached together, show one combined prompt offering both optional suggestions, with the same Continue/Snooze/Take a break choices applied to both due reminders. This prevents one reminder from starving the other or showing a second prompt immediately after dismissal. A pending prompt never accumulates repeated copies. Advance thresholds from the user's response, not by replaying every crossed interval.

## Quiet hours and time zones

Elapsed and snooze minutes use active monotonic time; they do not depend on a clock zone. Quiet hours use the existing notification preference owner's `start`, `end` and explicit valid `timeZone`, not a second healthy-use delivery field. An unset quiet-hours choice is off, not all day. Start equals end is invalid under the existing owner. An overnight interval crosses a calendar date in the selected zone.

When the healthy-use interface consumes that shared window, explain that it also pauses these optional on-screen reminders. This is a new integration requirement for the future reminder runtime, not a claim about today's notification-only behavior. Timing may continue during quiet hours under the ordinary eligibility rule, but no prompt is displayed. At window end, drop overdue reminders and schedule fresh thresholds from the then-current active total; never replay a backlog. Existing push/email quiet-hours behavior remains owned by delivery and is not rewritten by this rule.

Reuse the existing zone calculation: a skipped local start/end moves through the daylight-saving gap, a repeated start uses its earlier occurrence and a repeated end its later occurrence. Compare resolved instants. The interface shows the saved zone and lets the owner deliberately change it; travel or browser detection never silently changes an account schedule. If the current quiet-hours value cannot be loaded or validated, pause optional prompts until it can be resolved and show timing as unavailable, while preserving ordinary app access.

Quiet hours do not log out the user, deny reading or messaging, change event times, suppress recovery/verification mail, or automatically convert an optional adult reminder into a hard limit. A currently visible reminder is dismissed when a newly effective quiet period begins; its overdue state follows the same drop/reschedule rule.

## Interface contract and truthful enforcement

The future single Settings layout and reminder runtime must expose these distinctions with plain labels:

| State                        | Required explanation and available action                                                                                                                                                                                  |
| ---------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Optional adult choice        | “Optional reminder. You can continue, snooze or turn this off.” Show the chosen interval and the current browser-session scope.                                                                                            |
| Session estimate             | “Estimated active time in this browser session. Background time and other devices are not included.” Where applicable, explain reload/tab-local limits. Never label this total as time reading Scripture or doing service. |
| Paused or unavailable timing | Say whether the session is idle, hidden, paused for a break or unable to load its current settings. Unknown timing is unavailable, not zero minutes. Keep ordinary app access.                                             |
| Unsaved or failed preference | Distinguish the edited requested value from the last confirmed effective account value and offer retry without duplicate updates.                                                                                          |
| Quiet hours                  | Show the selected time zone and that optional reminders/eligible alerts pause. Essential account access and recovery remain available.                                                                                     |
| Future child limit           | Only a live, separately authorized family resolver may say “Managed family limit” and explain its actual enforced scope. An adult reminder, browser cookie or disabled control cannot make this claim.                     |

Example first-milestone copy at the default interval: “You have about 30 minutes of estimated active time in this browser session. Would you like to pause and spend time in the Word?” For the second prompt: “You have about 60 minutes of estimated active time in this browser session. Would you like time away or an opportunity to serve someone?” Always render the actual rounded current session estimate in that sentence, including later recurrences; show the chosen reminder interval separately. An interval is not the session total. Avoid guilt, urgency, moral scores, streak loss, public rankings or praise for accepting a prompt.

Use a dismissible nonblocking region with an accessible name and a polite announcement. Do not steal focus, hide an in-progress form, interrupt an account recovery/MFA flow, create a keyboard trap, use sound by default or force a route change. Defer an eligible prompt until an essential security/recovery interaction finishes; then show at most one current prompt. Respect reduced motion and enlarged text. Leaving or dismissing the prompt preserves unsaved work and existing explicit navigation protections.

Adult reminder enforcement consists only of when an optional prompt may be displayed. Server-owned autoplay preferences may prevent a supported player from automatically queuing another item; finite clip choices may stop automatic continuation within that player. Those are separately implemented behaviors, not device-wide access restrictions. A user can deliberately continue ordinary adult use. Unsupported players/providers must be labeled unsupported instead of promising that a preference controls them.

Child enforcement is a separate release gate: current guardian authority, child identity/age policy, server-evaluated limits, shared cross-device accounting where claimed, correction/time-zone rules and essential help/recovery access must be accepted by the family owner. The adult runtime consumes that resolver rather than implementing another policy engine. Local Continue/Snooze/off values must never override an active server-enforced child rule. When no accepted family resolver exists, leave family controls unavailable; do not substitute this adult clock or activate child access.

## Privacy, persistence and later acceptance

Saved reminder choices are private account preferences, owned by the current session with expected-account checks, versions and exact retry semantics. A church or another adult cannot change them or receive usage reports. Until its separate history feature exists, the active counter and prompt state are transient and are not uploaded, retained as analytics or exported as a behavioral history. Clear them on account change. Reading-preference reset does not reset reminders or another policy family.

Later optional history or cross-device aggregation requires its own disclosed scope, current choice, bounded data/retention, deletion and export behavior. Do not reuse private prayer activity, Bible reading logs, message contents, platform analytics or page visits to infer an adult's faith or to reconstruct time from missing observations. Enabling reminders does not authorize that collection. Reminder delivery is local and does not grant push/email consent or create a background scheduler.

Implementation acceptance must cover independent off-by-default choices; custom intervals; current-account changes; failed saves and exact retries; Continue/Snooze/disable/break; simultaneous due reminders; hidden/idle/focus/suspension/reload; multi-tab scope; clock changes and both daylight-saving transitions; quiet-window changes and load failure; no overdue burst; keyboard, enlarged text and reduced motion; unsupported external playback; and separation from analytics and family authority. A test must explicitly prove that an adult can decline without losing ordinary app access, and that no browser choice can claim or override a child hard limit.

This document changes no runtime, schema, configuration, provider, notification behavior or measurement policy. Thirteen existing settings-scope/privacy/registry and regional-format tests pass, including source-instant and daylight-saving preservation. Source reconciliation, private-data/copy scans, formatting and diff checks pass. The state contract was reviewed for simultaneous thresholds, failed saves, stale quiet-hours state, recurring elapsed labels and account changes. These checks do not claim that the new timer, reminder interface, persistence or child enforcement exists. Integration of this contract is separate from the dependent persistence, interface, timer, playback and verified-release acceptance.
