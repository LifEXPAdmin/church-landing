# Canonical media catalog metadata and audiences

## Scope and current implementation

September 18, 2026 candidate. This is the metadata and audience contract for a curated catalog of sermons, podcasts, testimonies, services and teaching. It specifies one record identity and the inputs that later catalog, publishing and search implementations must preserve. It does not implement their database, endpoints, interface or playback.

The inspected integrated baseline is `9e66724`. `resource-contracts.ts` reserves `mediaCatalogItem`; `requireImplementedResource` rejects it. Existing `MediaAsset`, `media-access.ts`, image processing, personal photos and albums own still images, not a sermon catalog. Post `scripture` is existing free-form member text, not normalized catalog metadata. Existing post, image, calendar, church, settings and sharing contracts keep their behavior.

Reuse `ResourceReference<"mediaCatalogItem">` for a canonical address, the current session/lifecycle and exact-retry boundary, `effectiveChurchGrants` for scoped church authority, and the existing discovery language IDs. No generic resource reference, church attribution, post permission or image ownership activates media publishing. The separate publishing-permission contract must bind allowed operations to current authority before writes are enabled.

The [publishing and source policy](MEDIA_PUBLISHING_CONTRACT.md) now defines the
proposed scoped editor/manager operations, bounded external source allowlist,
pre-save audience warning, rights review and playback/failure requirements.
This remains a definition: accepting it does not activate the reserved resource
or satisfy the later catalog service, interface, provider and release checks.

## One identity and explicit ownership

Every media item has one server-generated opaque `id`, regardless of editorial format or audio/video presentation. Its canonical address is `{ kind: "mediaCatalogItem", id }`. Save, share, search, report, playlist and future playback references point to that identity. A change to title, source URL, format or metadata increments `version` without allocating another item or losing references. A service recording and an extracted sermon are distinct items only when they are deliberately published as distinct editorial works; they may later carry a source relationship, never an inferred shared ID.

Provider IDs, URLs, church IDs, image IDs, series labels and post IDs are not media IDs. Two publishers linking the same external source remain separately owned catalog items. A retry of the same accepted create command returns its original ID. URL deduplication may offer an owner a warning, but never merges another owner's record or leaks its existence.

Ownership is exactly one of `{ kind: "personal", userId }` or `{ kind: "church", churchId }`. Resolve it from the current authenticated command and canonical server records, not a trusted client display name. `createdBy` identifies the actual accountable actor separately and is not part of a public projection. Changing a credited church, speaker or series never transfers ownership. Owner transfer is unsupported in the first contract; it requires a separate explicit current-authority transition, preserved history and rights reassertion.

A church owner requires the current approved and activated managed church plus a scoped publishing duty accepted by the publishing-permission contract. A directory listing, follow, display title, church position, old grant, event volunteer role or personal account claiming to represent a church is insufficient. Losing an individual editor's duty prevents further access to management; it does not transfer church-owned records to that person. Current church withdrawal, account restriction and moderation rules still apply to reads and publication.

## Shared record fields

These are contract fields, not a new Prisma schema or permission-bearing client payload. Bounds are server-enforced after trimming outer whitespace and normalizing line endings. Plain text remains plain text; do not accept raw HTML or silently truncate it.

| Field                    | Meaning and validation                                                                                                                                                                                                                                                                        |
| ------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `id`, `version`, `owner` | Canonical identity, positive integer optimistic version and the exclusive owner above. Server-owned, never replaced from an edit body.                                                                                                                                                        |
| `state`                  | `DRAFT`, `PUBLISHED`, `UNPUBLISHED` or `REMOVED`. Moderation restriction is a separate current read gate; a state label cannot bypass it.                                                                                                                                                     |
| `title`, `description`   | Required nonblank title up to 160 characters; optional description up to 5,000. No title inferred from a source URL or private filename.                                                                                                                                                      |
| `format`                 | One editorial discriminator: `SERMON`, `PODCAST`, `TESTIMONY`, `SERVICE` or `TEACHING`. It determines the permitted detail object below.                                                                                                                                                      |
| `presentation`           | `AUDIO` or `VIDEO`, separate from editorial format. Native uploads, livestreams and short-clip extraction are not enabled by these values.                                                                                                                                                    |
| `durationSeconds`        | Optional positive safe integer, at most 604,800 seconds. Unknown is `null`, not zero. Label manually supplied duration as supplied metadata; it does not prove playback, attention or attendance.                                                                                             |
| `languageIds`            | Zero to five distinct IDs from `data/discovery/languages.json`, validated by the existing discovery-language owner. Empty means unclassified, not English or the viewer's preference. Multiple spoken languages do not imply captions or translated editions.                                 |
| `speakers`               | Zero to ten ordered credits, each with nonblank display name up to 120 characters. An optional canonical account reference requires a current permitted association and must disappear when no longer disclosable. Names alone grant neither account links nor editing duties.                |
| `churchCredit`           | Optional supplied attribution with a nonblank plain-text name up to 160 characters. An optional canonical church reference requires a current permitted association and disclosure check on every projection; remove the link when it is no longer disclosable. A supplied name is labeled as attribution and grants no ownership, publishing duty, verified association or endorsement. |
| `series`                 | Optional publisher-owned label up to 160 characters, plus an optional positive integer sequence. Labels are not globally unique. A later canonical series ID must be scoped to its owner; the catalog item keeps its own ID.                                                                  |
| `topics`                 | Up to twelve distinct, publisher-selected ordinary topic labels, each up to 40 characters. Editorial metadata is not a viewer's belief, need, diagnosis or inferred interest.                                                                                                                 |
| `scripture`              | Up to twenty structured reference ranges under the normalization contract below. Original publisher input is retained for correction. Free-form post Scripture text is not migrated or automatically interpreted.                                                                             |
| `recordedOn`             | Optional supplied calendar date, distinct from server `createdAt`, `updatedAt` and `publishedAt`. Preserve date-only semantics; never infer attendance, recurrence or an event time zone from it.                                                                                             |
| `source`                 | Exactly one current external audio/video source in the first version, with source kind, validated URL and any recognized provider identity. Source replacement is versioned; a URL is neither a rights grant nor access control.                                                              |
| `artwork`                | Optional currently permitted canonical image reference and supplied alt text. Missing, retired or inaccessible artwork yields a readable text card. Do not expose storage paths, reuse a private original as a public thumbnail or treat an existing image purpose as a catalog upload grant. |
| `audience`               | Explicit `PUBLIC`, `MEMBERS` or `CHURCH`, using the matrix below. Unrecognized, absent or legacy audience values are unavailable until explicitly corrected by an authorized owner; never default to public.                                                                                  |
| `rightsAssertion`        | Private accountable attestation scoped to source, applicable artwork/text, intended audience and policy version. Publication requires a current accepted assertion; public attribution is a separate, minimal field.                                                                          |

Use existing body-size, identifier, request-key and expected-account protections when implementing these fields. The first persistence task must reject unknown writable properties and incompatible format details. Draft validation may retain incomplete fields as explicit missing values for their owner; publication must report the missing requirements without discarding the draft. Text normalization must not alter a member's quotations or source-provided proper names.

## Editorial formats

All rows use the same shared record and identity. Nullable fields are optional supplied metadata. Drafts may retain an explicitly missing detail object or discriminator with a field error. Publication requires the selected format's detail object, an explicit podcast `episodeKind` when applicable, and an explicit testimony `subject` when applicable. Missing testimony subject must never default to SELF; CONSENTED_OTHER requires a current permission basis referenced by `consentReference`. These details do not create parallel sermon, podcast, testimony or service records.

| Format      | Permitted detail object                                                                                                   | Boundaries                                                                                                                                                                                                                                                  |
| ----------- | ------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `SERMON`    | `sermon: { preachedOn: date or null }`                                                                                    | Scripture, speaker, series and church credit use shared fields. A preached date is not an attendance record.                                                                                                                                                |
| `PODCAST`   | `podcast: { season: positive integer or null, episode: positive integer or null, episodeKind: FULL or TRAILER or BONUS }` | Season/episode are publisher numbering, not identity or automatic RSS import.                                                                                                                                                                               |
| `TESTIMONY` | `testimony: { subject: SELF or CONSENTED_OTHER, consentReference: opaque private reference or null }`                     | Another person's story needs a current recorded permission basis before publication. The private reference/evidence and contact details never enter search cards or public metadata. SELF does not grant rights to third-party music, images or statements. |
| `SERVICE`   | `service: { occurrenceId: permitted canonical occurrence or null }`                                                       | A recording may stand alone. An occurrence reference must be currently readable and owned/associated appropriately; its private details cannot be exposed through the recording. This does not mark anyone present.                                         |
| `TEACHING`  | `teaching: { lessonNumber: positive integer or null }`                                                                    | A lesson is editorial material, not an accredited qualification or a generated Bible translation.                                                                                                                                                           |

Reject fields from another discriminator rather than silently storing hidden leftovers. On a format change, show incompatible fields and require an explicit replacement detail object in the same versioned command. Preserve previous values only in permitted private audit history, never in another format's public projection. The common ID, ownership and references survive the change. Do not publish personal testimony without the publication contract's rights and privacy review.

## Scripture reference normalization

Use a versioned reference registry that declares supported book identifiers, accepted names/aliases and chapter/verse bounds for its stated reference system. The namespace and version are stored with every normalized range. Do not silently choose a denominational canon, merge different numbering systems, invent a verse bound or claim that a translated display name denotes a different book. The parser/search task owns the actual reviewed registry and alias coverage; no such registry or parser exists in the inspected source yet.

Each normalized range has `referenceSystemId`, `referenceVersion`, stable `bookId`, `start: { chapter, verse }` and `end: { chapter, verse }`. Chapters and present verses are positive integers. A `null` verse denotes an explicitly whole-chapter boundary, not verse zero or missing validation. Keep the original supplied reference string separately. Split a multi-book expression into separate ranges; never compare unrelated books by alphabetical name or an invented universal numeric position.

Normalization procedure:

1. Trim outside whitespace and normalize repeated spacing for parsing, preserving the original text for correction. Resolve a complete book name or an explicitly registered alias case-insensitively; numeric book prefixes are part of the name. Unknown or ambiguous input produces an actionable error or unclassified draft text, never a guessed public search key.
2. Accept a single chapter, chapter range, single verse, same-chapter verse range or cross-chapter range within one book. Expand only the omitted end chapter of an unambiguous same-chapter expression. A book-only tag represents that book's declared complete span. Lists become bounded separate ranges.
3. Check every chapter and verse against the selected registry. Reject zero, negative, fractional, out-of-bounds and reversed endpoints. Mixed endpoint forms that cannot describe a complete unambiguous interval require correction. No silent swap, clamp, truncation or invented last verse.
4. Compare ranges only within the same book, reference system and compatible declared version. Expand whole-chapter boundaries using that registry when evaluating overlap. Intersect inclusive start/end coordinates; do not search by substring, and do not equate `John` with `1 John`.
5. Deduplicate identical normalized ranges without losing original-input provenance. Edits revalidate the whole set. An unsupported reference system remains explicitly unclassified until its owning adapter exists; no cross-system translation is inferred.

Required examples for the later parser/search implementation, using a registry in which these names and coordinates are valid:

| Input or comparison                                                | Required result                                                      |
| ------------------------------------------------------------------ | -------------------------------------------------------------------- |
| `John 3:16` and registered alias `Jn 3:16`                         | Same book and point, only if `Jn` is explicitly registered for John. |
| `John 3:16-18` and query `John 3:18-20`                            | Overlap at verse 18.                                                 |
| `John 3` and query `John 3:16`                                     | Overlap within the explicitly whole chapter.                         |
| `John 3:36-4:2`                                                    | One valid cross-chapter range; no loss of the end chapter.           |
| `1 John 3:16` versus `John 3:16`                                   | Different books, no match.                                           |
| `John 3:18-16`, `John 0:1`, unknown name or ambiguous abbreviation | Field-specific validation error; retain the edit for correction.     |
| Same-looking coordinates in incompatible reference systems         | No implicit overlap or conversion.                                   |

This metadata contract grants no Bible-text reproduction, translation, audio or provider license. Displaying a reference is separate from serving an edition or sending private material to an external provider.

## Visibility, current authority and projection

Initial first-party audiences have these exact meanings. They are not a universal audience ranking shared with photos, calendars or posts.

| Requested access                                                    | Published `PUBLIC`                                                                      | Published `MEMBERS`                          | Published `CHURCH`                                                                 | Draft, unpublished or removed                                                                                                    |
| ------------------------------------------------------------------- | --------------------------------------------------------------------------------------- | -------------------------------------------- | ---------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| Guest                                                               | Minimal public record only, if its source is permitted for that audience                | Unavailable                                  | Unavailable                                                                        | Unavailable                                                                                                                      |
| Current eligible adult account                                      | Current public projection                                                               | Current eligible platform-account projection | Only for the owning church's current approved connection and current access policy | Unavailable unless independently authorized to manage that exact record                                                          |
| Current personal owner or church publisher                          | Same audience projection for viewing; separate current management authority for editing | Same                                         | Same; a publisher duty is not an unrelated church membership                       | Own permitted draft/unpublished management projection; removed-body access only under the accepted retention/moderation contract |
| Revoked, restricted, erased, blocked or otherwise ineligible access | Apply the current source, owner, relationship and moderation rules; no cached allowance | Unavailable                                  | Unavailable                                                                        | Unavailable unless a distinct current scoped safety authority explicitly permits the action                                      |

`CHURCH` is permitted only for a church-owned item and means that exact owner church, never a user-supplied unrelated church or followers of a listing. Personal first-version ownership may select PUBLIC or MEMBERS. Family/child, group, private-invitation and business audiences remain outside this contract until their own source and authority owners exist. Management duties, publication duties, membership and public viewing are separate checks. Account closure and church deactivation must not leave a formerly private record readable by falling back to another audience.

The required audio/video source and current item audience together gate access to the item. Optional artwork, occurrence links, speaker-account associations, transcripts and related records are independently projected only when currently readable; omit denied fields or use a safe text fallback without hiding an otherwise readable item. If a referenced source establishes the item's audience or rights, it is a required access dependency and cannot be treated as optional to bypass that restriction. No optional reference exposes private details through a wider catalog wrapper. Denied item readers receive an indistinguishable unavailable response without title, source URL, artwork, format counts or hidden owner identity. Search facets and totals derive only from the same readable set; pagination cannot reveal inaccessible rows. Shared URLs and QR codes never authorize access.

Public and member views contain only the permitted descriptive metadata, safe source action and public attribution. They omit private rights/consent evidence, assertion actor and source fingerprints, management history, account contacts and internal storage/provider credentials. A public credited name is a supplied credit, not permission to expose the credited account's private profile fields.

An external link cannot make its provider enforce platform membership. For the first curated-link version, do not accept provider login secrets, private signed URLs or bearer access tokens as catalog sources. A restricted catalog record can limit discovery on this website but cannot promise secrecy of an already public provider resource. The publisher must see that distinction before publishing MEMBERS or CHURCH metadata. Genuine restricted audio/video requires a separately accepted delivery adapter that enforces current audience at playback; absence of that adapter means unavailable, not a public fallback.

Use PUBLIC-only metadata, sitemaps and previews after current permission checks. Restricted and denied pages use generic no-index metadata. Audience narrowing, unpublishing, source withdrawal and current authorization changes must invalidate list/detail/search/share projections and prevent old source URLs from being returned by the application. Do not claim to erase previously downloaded files or control a provider's independent public page. No provider call, embed, autoplay or remote artwork request occurs merely because the dictionary/registry names a source.

## Rights assertions and source changes

Before publication, the accountable publisher must assert an explicit basis: own material, permission for the intended use, or a specified license permitting that use. Record the assertion actor, server time, policy version, basis, source fingerprint/version, intended audience, required attribution and any expiry/withdrawal boundary. A claimed license or permission is a publisher assertion, not independent verification or a platform endorsement. Missing or expired evidence blocks publication and any dependent access that requires it.

Store private evidence and testimony consent references separately from public credit text. Do not publish personal contact information, contracts, signatures or private correspondence. A source, owner, restricted-audience widening, third-party artwork or transcript replacement requires the relevant current assertion to be reviewed and reasserted for the changed scope. An exact unchanged retry must not create extra assertions or silently refresh their expiry. Preserve current rights and access checks before replaying a historical successful operation.

The source-link implementation must parse URLs server-side, use an explicitly supported HTTPS destination policy, reject unsupported schemes, embedded credentials and private/token-bearing destinations, and preserve metadata after a failed save. Do not fetch arbitrary URLs to infer metadata, proxy private networks, copy provider cookies or extract remote media in the contract task. Provider acceptance, terms, embedding policy, processing budgets and native uploads belong to the separately scoped publishing/provider work.

Rights withdrawal, takedown or source loss must make the affected item unavailable immediately under its current owner/policy, remove it from discovery and stop source delivery. Retain only permitted minimal history for correction, audit and retention. A removed item stays a reference tombstone in private saved collections where permitted; it does not become another media item or expose removed text.

## Implementation and acceptance boundary

The catalog persistence owner will consume these fields with the existing same-origin/expected-account, strict payload, optimistic version and exact-body receipt rules. The publishing owner supplies the scoped current duty and rights enforcement. The library/detail owner consumes only authorized projections. Search and Scripture owners use bounded server queries and the approved registry; playlists, clips, progress, transcripts, artist profiles and Bible tracking retain their own tasks. Do not ship working-looking controls until those real adapters exist.

Required acceptance cases for those implementations:

- Create each editorial format through one identity owner; retry without duplication, edit without a new identity and reject cross-format fields. Metadata/source edits preserve existing references.
- Preserve unknown duration/language, missing artwork/transcript and a standalone service recording without fabricating values or hiding the whole record.
- Reject unauthorized owner selection, stale editor grants, another church's audience, source-audience widening and a missing or outdated rights assertion. Prove direct reads, writes and historical retry paths recheck current authority.
- Validate normal and malformed Scripture cases above, cross-system separation, alias stability and overlapping ranges without collecting Bible reading activity.
- Revoke access and verify lists, details, counts, facets, previews, source delivery, saved references and export omit private values. Distinguish no matching visible items from unavailable sources.
- Preserve draft edits on validation or provider failure; show actionable errors and explicit unavailable external playback. Do not add autoplay, provider contact or native upload as a side effect.

This candidate changes only this document. No runtime schema, route, permission, registry state, provider, migration or configuration is changed. The two existing resource-contract tests pass, preserving reserved-source denial and implemented-owner separation. Source-owner, copy, private-data and formatting checks pass. A focused read-only review found two ambiguities, now resolved: optional denied references use safe omission/fallback while required access dependencies gate the item, and publication requires explicit podcast/testimony discriminators with a current third-party testimony permission basis. No new runtime, full-suite, browser or production acceptance is claimed for this document-only change. Integration and acceptance of the later catalog implementation remain separate; a merged definition does not make the catalog live.
