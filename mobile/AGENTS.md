# Shared mobile working instructions

Recorded 7 October 2026. Apply the root instructions and current human request.
This package is one native codebase with iPhone and Android platform adapters.

## Read, select and reserve

1. Read the current private mobile master plan, complete coding runbook (including
   Continuous execution and Canonical website prerequisites), source map and
   website-to-app portability audit. Read both mobile queues and relevant website
   tasks before selecting the earliest eligible unfinished work in this lane.
2. Inspect the actual checkout, all relevant worktrees and current website
   behavior. Remote main can be older than local tested work. Record source,
   runtime and release identities separately.
3. Reuse valid source-reading records with exact paths and source revisions.
   Inspect full affected modules, tests and changed dependencies. A file inventory,
   import list or old report does not mean its source or behavior was verified.
4. Use a distinct registered worker and isolated worktree/branch. Atomically
   reserve exact task IDs and file/contract scope through the repository's
   coordination script. Inspect active claims and coordinate with their owners.
   Never infer abandonment from age or change another worker's runtime.

## Keep one canonical implementation

The dedicated mobile queue owns native presentation, platform integration and
cross-platform acceptance. Canonical backend, API and reusable-package work stays
on the original website task. Either mobile lane may assist eligible unclaimed
shared work, or accept an explicit handoff, using that original task and exclusive
scope. Consume committed, verified receipts; do not copy server policy, invent a
second account system or implement a parallel typed transport.

Follow the [shared-core feature recipe](../docs/godschurches/SHARED_CORE.md#add-a-feature-through-the-existing-boundaries)
for the service, contract, adapter, UI and verification sequence. Its first-journey
source map identifies existing owners; it does not replace native device proof.

Keep pure state separate from UI, semantic design tokens separate from layouts,
and storage/link/lifecycle adapters separate from domain contracts. Do not import
Next, Prisma, server-only modules or browser globals into native runtime code.
The initial journey is sign-in, bounded feed, post detail and safe sign-out.
Expand only after its dependencies and acceptance are ready. Fixture screens
must identify fictional data and cannot stand in for real session acceptance.

## Execute and verify

Continue authorized useful work without routine permission pauses. Make
reasonable reversible choices and fix routine code, dependency, configuration
and test problems. A genuine dependency block holds the dependent acceptance;
record it precisely and continue another useful independent step.

Use the guarded workspace launcher in [README.md](README.md). The default profile
requires the prepared external SSD. A separately inspected host may use an
explicit private host/volume/workspace profile with verified writable storage
and headroom. Record that host's authorization, storage receipt and task ownership
before large writes. Never fall back to another disk when a profile fails.
Retain source/history and keep generated data task-scoped. Reserve the machine-build
contract for install, runtime, export and native builds. One worker runs heavy
work on the shared Mac at a time. Inspect port ownership before starting local
services and gracefully stop only services owned by this task.

Run meaningful checks for the changed boundary. Repeat or broaden them when a
change, failure or unresolved concern warrants it. Do not run unchanged loops or
poll an occupied resource while useful independent work exists. Separate source
review, unit checks, JavaScript exports, native builds, simulator/device behavior,
size measurements and store acceptance in every receipt.

After each coherent code result, save the tested commit and update the existing
private task and matching Session Log history. Include source/build identity,
checks actually run, failure/fix evidence, remaining gates and an exact next
action. Preserve prior attribution and labels. Hand off shared interfaces to the
other lane and continue; a progress report is not a stopping point.

## Real gates and stopping

Keep owner identity, signing, credentials, accessibility, security and release
gates intact. Development authority does not create purchase, production,
provider or store-release authority. Do not weaken audience/session checks to
make a fixture or screen work. Record prepared owner actions in the existing
private task system while continuing independent work.

Before stopping, check eligible tasks, independent partial work, committed
handoffs and permitted shared assistance. Stop only on a human stop, when no
useful authorized work remains, or an actual access/runtime/resource limit.
Save the exact next action, claims and owned processes. Release claims only with
a durable checkpoint; never leave completion or release acceptance implied.

Keep private workspace links, task IDs, personal paths, device identifiers,
credentials and private test evidence outside this public repository.

Storage clarification, 8 October 2026: a recorded handoff to another Mac uses its
own verified host profile. This does not change the original Mac's SSD default
or permit an implicit internal-disk substitute.
